# CYY 小陈公众号文章创作示例

## 示例 1：科技热点改写

### 用户输入

"参考这篇文章，帮我改写成 CYY 小陈风格的公众号文章。"

### 阶段 1：直接交稿

先在内部完成风格解构和事实核对，例如：

**骨架分析**

- 原文从热点事件切入。
- 中间解释产品/工具变化。
- 结尾给出影响判断。

**血肉分析**

- 保留核心事实、产品名称、关键功能和原文观点。
- 删除重复铺垫，补充开发者视角。

**气质分析**

- 原文偏资讯。
- 新文改成程序员朋友式分享，轻松但不乱嗨。

只生成一个 CYY 小陈版本：

- 开头固定："大家好，我是CYY小陈。"
- 前 5 段讲清楚今天聊什么、为什么值得关注、读者能收获什么。
- 用短段落、小标题和「最后哔哔」收束。

发送前 Humanize，检查并优化：

- 是否像真人经验分享。
- 是否有模板化总结。
- 是否有过度正式的表达。
- 是否自然出现「我」「你」「大家」。
- 是否嵌入已核实的本地配图；必要但尚未取得的素材是否清楚标注。

首条实质回复直接把完整文章发到聊天框，并附同内容、可打开的 `.md` 文件链接。预览文件保存在当前任务的可交付输出目录；此时无需询问最终保存根目录。

### 阶段 2：修改定稿

用户要求修改时，同步更新聊天框预览和原 `.md` 文件，不累积多个草稿。

### 阶段 3：保存位置确认

读取：

```text
memory/save-roots.json（相对于当前已安装的 cyy-writing 技能目录）
```

如果有 `lastRoot`：

```text
这次还是保存到上一次的位置吗？

上一次：D:\公众号文章

也可以换一个新位置。你只需要发我根目录绝对路径。
```

如果用户换新位置，更新记忆文件，只保留最近 3 个根目录。

### 阶段 4：保存文件

创建：

```text
D:\公众号文章\文章标题_2026-06-21\
```

保存：

```text
最终版.md
最终排版版.html
images\...
```

不要保存原始草稿、humanize 中间稿，也不要创建 `markdown/` 和 `html/` 子目录。

## 示例 2：教程类文章

### 用户输入

"基于这篇教程，帮我写一篇 Cursor 使用指南。"

### CYY 写法

结构优先使用：

1. 准备工作
2. 开始实战
3. 测试验证
4. 踩坑和解决
5. 最后总结

写法要求：

- 每一步讲人话。
- 关键操作用列表。
- 优先插入已取得的真实截图，尚未取得的必要截图清楚标注。
- 遇到坑要讲原因和解决办法。

## Humanize 技巧清单

1. 把"因此"换成"所以"，把"然而"换成"但是"。
2. 加入"我觉得""说实话""好家伙"等自然口语。
3. 允许短句和断句，不要过度修饰。
4. 用"你"直接和读者说话。
5. 避免连续排比和空泛判断。
6. 用具体例子代替抽象描述。
7. 不编造具体数据；原文没有的数据就不要硬补。
