# 两条路线示例

## 主题调研

用户：“写一篇 Gemini 新模型介绍。”

调研官方发布和模型说明，核实开放范围与价格；按 [X 案例环节](x-case-workflow.md) 搜索原帖并取得成品媒体，插入相关章节，解释读者应观察什么。交付含本地媒体引用的 `最终版.md`、`images/` 和素材 ZIP。此轮不生成 HTML。素材无法取得时明确缺口，不冒充实测。

## 模板改写

用户上传文章模板：“按这个模板改成 CYY 小陈风格。”

读取实际模板和媒体，保留用户明确指定的栏目，核实事实，用自己的表达写稿，将适用媒体提取/替换后放入对应段落。AI 主题同样完成 X 案例环节；模板只有榜单和宣传图时补充成品展示，无法取得时说明缺口。交付同样的图文 Markdown 与 ZIP，等待用户修改。

## 用户编辑后排版

用户在主 Markdown 改了两段，增加 `images/new-demo.gif`，再说：“改完了，生成 HTML。”

重新读取主 Markdown，核对新 GIF 引用与动画帧，以该文件生成 HTML，保留用户文字及素材順序，更新同一 Notion 页和素材 ZIP。

如果用户在 Notion 修改，先 fetch 当前稿件和媒体；把已上传媒体下载到本地 images/，保留可解析的相对引用，再生成 HTML。多个版本冲突时确定以哪份为准。

仅说“保存到 Notion”时保存 Markdown 阶段内容，保持待修改状态，不提前生成 HTML。
