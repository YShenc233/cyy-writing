# Notion 文章归档

## 目标与范围

每篇文章对应一个 Notion 页面，默认保存到用户已指定的“公众号文章”父页面。页面名使用 `YYYY.MM.DD-公众号标题`：导入旧文章优先采用原目录/文章中的日期，新文章采用用户当地写作日期；日期不明确时询问，不使用迁移当天日期冒充原写作日期。文章内的原始标题保持不变，记录写作日期与稿件状态。正文保持可编辑，配图在对应段落展示。首轮标记“待用户修改”，只保存素材来源记录、最终版.md、媒体和素材包；用户修改定稿后才加入最终排版版.html。上传/保存请求本身不触发 HTML。素材包保留 Markdown、HTML 与 images/ 的相对目录关系，包含本次实际生成的其他交付物。不要将内部分析或中间稿当成交付物归档。

Notion 原生正文与公众号 HTML 是两个视图：原生正文适合编辑，HTML 原文件保留微信公众号内联样式。Notion 不保证还原公众号排版；HTML 预览只是辅助，完整素材包中的原始 HTML 与图片才是可搬运的排版交付物。

## 位置与连接

1. 读取 `memory/notion-destinations.json`（相对已安装技能目录）。只记录用户已选定的工作空间、父页面或数据源 ID/URL、最近使用时间；不保存凭据。当前请求中的目标优先于历史目标。首次没有目标时在交稿后询问页面/数据库链接；不要擅自选择私人页面或创建数据库。
2. 用可用 Notion 连接读取身份/工具权限，再读取目标页面或数据库。数据库目标使用实际返回的数据源与字段，不猜测状态等字段。检查历史目标属于当前连接的工作空间。连接失败时保留本地交付物，报告错误并停止依赖连接的动作。
3. 读取 Notion 提供的增强 Markdown 规范：通过资源接口或 Notion fetch 读取 `notion://docs/enhanced-markdown-spec`，不用普通网页抓取器。正文转换与附件引用遵循当前规范。
4. 本技能的默认归档偏好只覆盖本次文章交付物，不授权迁移旧文章或改动无关页面。已有明确目标和保存请求时直接执行；目标缺失时只等待目标信息。

## 上传与写入

先完成当前阶段的本地交付文件与素材清单，再上传并保存页面。首轮仅包含 Markdown 阶段产物，不能为了归档要求提前生成 HTML。清单记录每个文件的相对路径、类型、字节数、SHA-256、上传状态和返回引用。来源记录保存原始 URL、获取日期、对应图片/段落及必要测试条件；无需把来源链接机械插入公众号正文。

- 本地图片、GIF、视频和大文件：使用当前连接的文件上传工具。若提供 `create_file_upload`，按其文档取得短期上传 URL，用一次 multipart/form-data POST 上传，文件字段和请求头严格按返回要求设置，multipart 文件部分的 MIME 类型使用返回的 content_type，避免 Markdown/HTML 因默认 text/plain 上传失败。当前单次上传上限为 20 MiB，仍受工作空间限制约束；执行时以工具实时文档为准。上传 URL 和签名头不写进日志或持久记忆。
- 小型 Markdown、HTML 或来源记录：可用 `create_attachment` 的文本内容上传；按文档核对 UTF-8 字节数上限（当前 200 KiB）。超过限制改用本地文件上传。上传成功后尽快将返回引用挂到页面，临时上传本身不等于归档完成。
- 使用上传响应的 `suggested_markdown` 或规范支持的引用放置图片/附件。HTML 使用规范要求的 embed，其他附件使用对应文件块；不猜测 file-upload 引用，也不把 HTML 当作原生文章正文。
- 正文中的本地相对图片引用须替换成 Notion 上传引用，保留说明文字。Windows 路径、file:// 和 localhost 不能作为 Notion 图片源。HTML 中的相对路径在 Notion 预览中也可能失效：保留原始 HTML 附件和可离线打开的素材包，明确预览限制；只有存在实际可用的媒体 URL 时才提供另一个替换引用的预览版，不用临时签名 URL 充当永久素材地址。
- 若任何文件超过当前上传能力或上传失败，保留完整本地文件，页面列出未归档文件及原因。只有清单全数挂载且验证通过，才能报告“全部归档”；不要只保存正文便宣称完成。

创建页时明确指定用户选择的父页面或数据源。先保存完整正文，再附来源与交付文件区域。大文章按工具要求分段写入，保证段落顺序；异步操作等待成功状态再进行依赖动作。

## 修改、重试与验证

将创建成功返回的页面 ID/URL 与文件清单保存到文章本地目录的 `notion-sync.json`，记录工作空间和目标 ID。后续修改或生成 HTML 前先读取并 fetch 同一页。用户在 Notion 修改的文章与媒体作为最新定稿来源：下载新上传媒体到本地 images/，替换为可解析的本地引用，再排版；不要用旧稿覆盖用户修改。用户在本地修改时以其明确指定的文件为准。定向更新文章和交付区域，保留用户额外添加的笔记、子页面和无关内容。附件修改后只替换对应引用，未变素材可复用已有引用。

写入结果不明时先检查已记录页面和目标下的实际结果，再决定是否重试；无法判断是否创建成功时报告不确定，不连续创建同名页面。上传或写入失败只对已确认未成功的项重试一次；仍失败则交付本地文件和缺失清单。

完成后回读页面及其附件引用，对照本地正文检查标题、各段落、列表/表格和配图位置；对照清单检查所有文件已上传并挂载，确认异步任务已成功。fetch 不证明实际视觉显示或下载字节一致：有可用浏览器时检查媒体展示，有下载能力时核对关键附件；否则明确验证范围。仅在首次目标成功验证后持久记录该目标，权限阻止记忆写入时保留任务目录中的记录并说明。

首轮交付包含 Notion 链接、归档状态、缺失项（如有）和图文 Markdown/素材包链接，随后等待用户修改。定稿后才交付 HTML 链接与公众号复制指南。
