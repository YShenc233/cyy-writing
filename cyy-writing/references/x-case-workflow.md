# X 案例与效果展示

用于 AI 主题调研和模板改写的第一遍图文 Markdown；修改案例时也沿用。目标是让读者在相关章节直接看到实际成品，理解它解决了什么任务、效果如何。

## 搜索并核对原帖

围绕准确模型名与正文中的具体能力搜索 X：写作章节找输入与成稿，办公章节找报告、文档或工作结果，编程章节找运行作品、交互和修复结果。优先查看官方账号、作品作者与测试者，同时关注失败或修改过程。按文章需要选择案例，不固定数量，也不把所有演示堆到文末。

X 站内搜索可用时直接搜索；登录限制或搜索结果不足时，可通过网页搜索和相关报道定位原帖，再打开原帖核对。搜索摘要和转载只作线索。无法读取原帖时记录访问限制，区分未核实线索与已核实案例。

核对作者、日期、准确模型版本、任务和对应媒体；记录可见的提示词、推理设置、尝试次数、修改轮次、运行时间与费用，缺失项保留为未知。沿原帖检查可运行作品和公开代码（如有），区分作者展示与本文亲测。

**版本确认直接决定案例能支持的结论。** 发布前 Arena 占位名、匿名模型或作者自称的新型号，只有开发商或平台明确映射到正式版后，才能当成正式版案例。否则如采用，紧邻媒体注明“发布前社区演示，未确认对应正式版”，只描述可见成品；其他已知型号按实际型号标注。单次漂亮演示不推导为普遍能力或稳定胜过竞品。

## 将效果放进正文

取得原图、实际演示视频或可运行作品的录制。视频可截取有代表性的 GIF：保持顺序和速度含义，保留模型标签、水印和影响理解的界面；记录原视频 URL、截取时间段、缩放和帧率。静态图轮播如实称为轮播。

把媒体保存到 `images/`，在对应章节用 Markdown 图片语法嵌入。每个案例相邻段落交代：

- **任务**：作者要求做什么，哪些输入或条件可见。
- **结果与观察点**：读者应看哪处文字、交互、细节或失败，为什么与本章节判断相关。
- **范围与不足**：官方演示、社区体验或作者亲测；版本是否确认；可复现条件和未公开信息。

榜单可支撑能力信号，宣传图可介绍产品，调侃 GIF 可表达心情；它们各自保留用途，不能计作实际效果案例。写作效果需要实际成稿；3D 编程视频不能填补写作样稿的缺口。

找不到所需案例时明确说明已检索的方向与证据缺口，把对应判断写成待验证的期待。找到原帖但取不到媒体时说明访问或获取限制，可保留原帖链接作为补充，不宣称已完成正文嵌入。

## 交稿检查

交付前确认以下条件，未满足项在交付说明中列出：

- 实际搜索了 X，并核对所采用的原帖，而非仅写出计划或收集赞美性评价。
- 每个用于展示效果的案例都有对应成品媒体，已插入相关章节，并说明任务、观察点与证据范围。
- 所引用本地媒体存在且能解码；需要动画的 GIF 有多个不同画面，预览能够加载，并与原演示对应。
- `来源记录.json` 记录作者、日期、原帖和媒体 URL、版本确认状态、已知条件、缺失条件和处理方式。
- MD、素材包和已授权的 Notion 正文使用同一批案例；后续定稿 HTML 保留用户修改后的案例与媒体顺序。

交付时给出图文 Markdown 和素材包链接，直接展示有代表性的案例媒体或图文预览。验证范围有限时如实说明，等待用户修改后再生成 HTML。
